# Changelog

User-visible changes to SemanticRouter.NET: the NuGet packages, the `semantic-router` tool, the container image and the desktop app. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/); before 1.0, a minor version can change behaviour. Each pull request with a user-visible change adds its line under **Unreleased** ([CONTRIBUTING.md](CONTRIBUTING.md#changelog)).

## [Unreleased]

### Added

- A gateway benchmark: `dotnet run -c Release --project benchmarks/SemanticRouter.Benchmarks -- gateway` measures what the router adds in front of a stub backend (time to first byte, total time, throughput and memory at 1, 8 and 32 clients), `--soak` watches for drift, and `--faults` checks failover, cooldowns, stalls, dropped connections, cancelled requests and two routers on one database. CI runs the short version on every pull request and the soak and faults nightly.
- `IRoutingActivityStore.PurgeWithResult` and `RoutingActivityLog.PurgeWithResult` say whether purged activity is also gone from the store's files (`ActivityPurgeResult`), and the store interfaces gain `IRoutingActivityStore.IdsBetween` and `IRoutingFeedbackStore.Remove`, for deleting what refers to purged activity. All are default interface methods: existing stores keep working. (#241)
- Dashboard: **Look up prices** on a connector's group on the Models page fills in its cloud models' input, output and prompt-cache prices (a subscription's API prices) from OpenRouter's public model list, and **Discover models** fills them in for the cloud models it suggests. Models are matched by their provider's own id at the price of the provider the connector reaches; a gateway on another host gets the model maker's price, marked to check. Nothing is applied until Apply & save. `POST api/prices/lookup` is the endpoint; the list is fetched only on request, kept for six hours, refused in offline mode unless `openrouter.ai` is allowed, and `doctor` lists it as an egress destination.
- Dashboard: a subscription model has **API cache read price** and **API cache write price** fields next to its API input and output prices, so its cached tokens are valued at what the API charges for them.
- `GET api/setup` for the dashboard's first-run setup: whether a model is still needed, what `semantic-router init` would find on this machine (LM Studio, Ollama, and the claude, codex and copilot CLIs with whether they are signed in) and one-click provider presets (LM Studio, Ollama, OpenAI, Anthropic, OpenRouter, Google Gemini, Claude Code, Codex, GitHub Copilot). It only describes; nothing is enabled until the dashboard applies it. The machine policy, offline mode and the allowed endpoints leave out what they turn off (offline, no CLI is started to ask). Like a change, it is refused from other sites, so a page elsewhere cannot set off the CLI checks; `?refresh=true` reuses a look younger than 10 seconds, and a detection that fails still answers with the presets and the problem in `detectionProblem`.
- `POST api/connectors/discover` discovers the models of a connector that is only in the dashboard's draft, held to the same checks as applying it (policy, what a CLI may run, where a stored secret may go). The audit log records where it asked (`scheme://host:port`, or a CLI's program).
- `POST api/config/save` and `POST api/config/revert`, and `unsaved` in `GET api/status`: a configuration applied without saving can be kept or undone, and the dashboard can say it is not saved.
- `PUT api/config?baseVersion=N&instance=X` refuses a change made against a version that is no longer running (`409` with who changed it, when and how), so two editors cannot silently undo each other. `instance`, a random id for this run of the router, is in every configuration envelope and `GET api/status`: version numbers start again at 1 on every start.
- Validation errors from `PUT api/config` and `POST api/config/validate` come with `issues` that name the field (`Routes.1.Name`, `Connectors.local.Timeout`), and a value that does not fit its field says the format it needs (`"5m" is not a duration; use hh:mm:ss, e.g. 00:05:00`) instead of "Expected a configuration document".
- The `semantic-router` tool and the desktop app redirect `/` to the dashboard (`MapRouterDashboardRedirect`; an application's own `/` endpoint wins).
- The start-up banner has a **Try it** block: a request to send (curl, or `Invoke-RestMethod` on Windows), where to watch it on the dashboard (`#/live`), and the Claude Code command as one line with its variables inline, as in the client guide. While no model is enabled it says so instead, with the link to the setup on the dashboard's Overview.
- The container seeds a connector for `OPENAI_API_KEY` and `ANTHROPIC_API_KEY` on the start that creates the configuration file (deleting one sticks); the connector refers to the key as `${env:…}`, so the key never lands in the file (`SEMANTIC_ROUTER_SEED_API_KEYS`, on in the image).
- `doctor` checks the Codex CLI's sign-in with `codex login status`.
- Desktop app: on the first start the dashboard opens on its Overview, where the setup is, and the welcome window says so. While the router has no enabled model, the tray menu says so and offers the setup, with one notification.
- README: a Quick start right under the introduction (who it is for, what to install, the commands, the desktop app, where to go next).
- Dashboard: **Running configuration not saved** in the top bar when the router runs a configuration that was applied without saving, with **Save** and **Revert to saved** for the admin (the More panel shows the source as "not saved").
- Dashboard: the save bar counts the draft's changes, and **Review** shows them next to the running configuration.
- Dashboard: Apply names the version the draft started from; when someone else applied a configuration meanwhile, a notice says who and when and offers **Reload**, **Compare** or **Apply mine anyway**. The refresh notices such a change too (a router restart included): it reloads a draft without changes quietly, and moves unapplied edits onto the new configuration when they touch other settings. Moving them is strict: a new order of model aliases, routes or models, or a list such as CLI arguments changed on both sides, is a conflict; only lists that are sets (utterances, capabilities and similar) combine.
- Dashboard: removing a route, model, connector, profile, tier, budget or memory source offers **Undo**; removing a connector that models use, or a profile that rules, virtual models, client mappings or budgets name, asks whether to remove those too.
- Dashboard: problems from Validate and Apply are shown next to their fields (the item opens, the first gets the focus), and the problem list links each one to its field on its page.
- Dashboard: model aliases can be reordered (the first matching glob wins).
- Dashboard: new Activity entries that arrive while the table holds still (auto-refresh off, a label being written, text selected) are counted, with **Show**.
- Dashboard: **Set up SemanticRouter** on the Overview while no model is enabled: add a connector (tools found on this machine first, then presets for LM Studio, Ollama, OpenAI, Anthropic, OpenRouter, Gemini and the CLIs), add models (Discover models, Apply & save), send a test prompt. Read-only users see that an admin needs to add a model.
- Dashboard: **Add connector** is a menu of presets and a blank connector, also shown on an empty Connectors page.
- Dashboard: Activity has a search box, and a click (or Enter) on a row opens the whole decision.
- Dashboard: Router learned has a small Settings form for the common `Tuning` options.
- Dashboard: Routes can be set to follow the conversation (`FollowsConversation`).
- Desktop app: the dashboard in the app window has an update banner when an update is ready, available or downloading (**Restart to update**, **Not now**), and **About SemanticRouter** under **More**. On macOS the app menu has **About SemanticRouter** and **Check for Updates…**.
- Desktop app: a **Settings** window with everything the tray menu sets or does (the router's status and problems, **Restart router**, the background service, start at sign-in, where the dashboard opens, the log and the configuration folder), opened from the tray, from **App settings** under **More** on the dashboard in the app window, and from the macOS app menu (⌘,). Nothing needs the tray icon any more.
- Desktop app: on Linux (libnotify 0.7.10 or later) a click on a notification opens what it is about. A failure you caused (the background service, a restart, an update download) is also a notification.
- `semantic-router init --enable-cli claude,codex` enables just the subscription CLIs named, without asking; the others found are added disabled. Without a terminal, `init` now says that it skipped the questions and how to choose (`--yes`, `--enable-cli`, `--no-cli`).
- Dashboard: **Admin → Service** for the `semantic-router` tool: who can connect (this machine only, or other machines too, and the port, saved to `semantic-router.host.json` and applied by a restart, with what serving other machines needs), **Restart** and **Stop**, and the background service (**Install and hand over**, **Reinstall**, **Remove the service**, its definition and logs). A restart happens in the same process; one onto a port that is taken goes back to the old address and says so. It says when `--urls`, an environment variable, `Kestrel:Endpoints` or a container decides where the router listens, and an application that hosts the router itself (or the desktop app) keeps its own controls. API: `GET api/service`, `PUT api/service/listen`, `POST api/service/{restart|stop|install|reinstall|uninstall}`, admin only and audited; hosts plug in through `IRouterServiceControl`.
- Documentation site: each video has a transcript (its narration, plus figures shown on screen that the narration doesn't say), a link to its captions file, and a download link that names the video. The build fails when a video is published without captions, unless `site/videos.json` marks it `"speech": false`.
- Before the state database is migrated to a newer schema, the file as it was is kept as `semantic-router.db.v<old schema>.bak`, so the previous release can be started on it again. [Upgrading and going back](docs/host.md#upgrading-and-going-back) describes both directions ([#205](https://github.com/siebe41/SemanticRouter.NET/issues/205)).
- Upgrades bring `semantic-router.json` up to the current built-in template: on the first start of a new release, routes, utterances, model aliases and defaults that still have an earlier template's values get the current ones, and settings you changed are kept. The start prints what changed, and the configuration history records it as an `upgrade` entry. The file is stamped with `"TemplateVersion"` (`RouterConfiguration.TemplateVersion`). The sample evaluation set is replaced too while nobody has changed it ([#204](https://github.com/siebe41/SemanticRouter.NET/issues/204)).
- Desktop app: `SemanticRouter --update --restart` applies an update as **Restart to update** does, starting the new version (and the background service, if it ran the app) once the update is applied. CI uses it to test the restart on Windows ([#212](https://github.com/siebe41/SemanticRouter.NET/issues/212)).
- Dashboard: **New defaults to review** on the Overview after an upgrade to a newer built-in template kept settings you had changed that the template changed too: each with yours and the new default, **Use the new default** or **Keep mine**. It is also a notice under **Needs a decision**. API: `GET api/config/template-defaults`, `POST api/config/template-defaults/use` and `…/keep` ([#204](https://github.com/siebe41/SemanticRouter.NET/issues/204)).
- NuGet packages: each has a readme on its nuget.org page (what it is, how to install it, a snippet, links to the docs), the app icon and a copyright. The five library packages publish symbol packages (`.snupkg`) to nuget.org's symbol server, so a debugger can step into their source through SourceLink and stack traces show line numbers. The symbol packages are also release assets ([#202](https://github.com/siebe41/SemanticRouter.NET/issues/202)).

### Changed
- Packages: `Microsoft.AspNetCore.Builder` and `Microsoft.Extensions.DependencyInjection` hold only the setup extension classes. `RouterDashboardOptions` moved to `SemanticRouter.AspNetCore`, `SqliteStateOptions` to `SemanticRouter.Storage.Sqlite`, and `SqliteStateBuilderExtensions` (`UseSqliteState`) to `Microsoft.Extensions.DependencyInjection` like the other packages' builder extensions. The dashboard API's request and response records and those of the classify, `/v1/models` and `count_tokens` endpoints (`PromptClassificationResponse`, `RouterModelInfo`, `TokenCountResponse` and the rest) are no longer public; their JSON is unchanged. Binary breaking: rebuild against this version, and add `using SemanticRouter.AspNetCore;` or `using SemanticRouter.Storage.Sqlite;` where code names a moved options type. (#250)
- Packages: 23 `SemanticRouter.AspNetCore` types that only the router itself uses are no longer public: the doctor (`RouterDoctor`, `RouterCheck`, `RouterCheckStatus`), the model lineup and model-family table (`ModelLineup`, `ModelLineupEntry`, `ModelLineupReport`, `ModelFamilyTable`, `ModelFamily`, `ModelFamilyBand`, `ModelFamilyFile`), the built-in memory sources, evaluation-set stores and file secret store (`ClaudeCodeMemorySource`, `KnowledgeGraphMemorySource`, `MarkdownMemorySource`, `InMemoryEvaluationSetStore`, `JsonLinesEvaluationSetStore`, `ProtectedFileSecretStore`), and `ActivityReports`, `RoutingFeedbackLog`, `MemoryExposureLog`, `SecretRedactor`, `ClientTurnFile`, `DashboardTheme` and `ThemeContrastIssue`. The interfaces they implement (`IMemorySource`, `IEvaluationSetStore`, `IRouterSecretStore`) stay public, and configuration selects the built-in implementations as before. Binary breaking. (#200)
- Dashboard: **Admin** opens on the new **Service** tab, and the Overview's "this machine only" note points there. The live event stream ends when the router stops, so an open Live view no longer holds up a restart.
- Usage (the Usage page, the digest and budgets) is priced at the catalog's current prices: changing a model's price, cache prices or API prices now changes its past usage too, instead of only requests served after the change. A model no longer in the catalog keeps its recorded cost. `IUsageLedger.Records` (a default interface method) hands out the records to price; a custom ledger that does not implement it stays at the recorded prices.
- Dashboard: the 19-link sidebar, which no longer fit a laptop screen or the desktop app's default window, is a narrow rail of five sections (Monitor, Routing, Providers, Gateway, Admin) with each section's pages as tabs under the top bar. Routing rules is the **Rules** tab and the gateway page the **Settings** tab. **Report an issue** (the Feedback page) sits at the foot of the rail, and the version, theme picker and **Sign out** moved under **More**. Every page keeps its address, so existing links and bookmarks still work.
- A request no model can serve because of the configuration (no model enabled, or none with the tier, capabilities, locality or profile it needs) gets `400 invalid_request_error` in the client's protocol instead of `503`, so the SDKs and Claude Code stop retrying, with what to do and where: "SemanticRouter has no model that can answer this (no model is enabled). Add one on the dashboard: http://localhost:5080/router#/overview". Failed or cooling-down models still give a retryable `503`, as do a prompt that could not be classified (the embeddings did not answer) and a request only models outside their active hours would fit ("no model is in its active hours right now").
- The "no model is enabled" warning and service note point to the dashboard's setup on Overview instead of the Models page or `semantic-router init`.
- `init` replaces a configuration that still holds the built-in template (as the router writes it on its first start) without `--force`; a file whose embeddings someone chose is not the template.
- `init` output: a one-line tier legend, no similarity-threshold note, the Claude Code command on one line (no `export`) and only when a model is enabled; with none, the dashboard's setup. When a subscription CLI is all it found, the question says that without it the router has no model to use.
- `doctor`: no enabled model is a `[FAIL]` (exit code 1), whose fix is a step that helps (the dashboard's setup, or `init` while the configuration is still the template). Fix lines name the dashboard field beside the setting, e.g. *Providers → Connectors → openai → API key*.

- A failed ONNX model download names huggingface.co, `HTTPS_PROXY` and `Network:CaBundle`, and where to copy the file instead, and is logged without a stack trace.

### Fixed

- The container image reports its release's version. Released images were built as 0.1.0 whatever their tag, so the dashboard, `GET /router/api/status`, `semantic-router version` and the image's SBOM all named the wrong version. The image now also carries the OCI labels `org.opencontainers.image.version`, `.revision`, `.source` and `.licenses`, and the release fails unless the image, its labels and its SBOM name the tag's version. (#219)
- `THIRD-PARTY-NOTICES.txt` lists everything the deliverables ship. The Inter and Fira Sans fonts the dashboard embeds (SIL OFL 1.1) are listed everywhere. The desktop app's notices also list Velopack's native updater, setup and stub, and the Linux AppImage runtime with the libraries it links (musl, libfuse, squashfuse, zstd, zlib). Every entry names an SPDX licence and has its text in the file: the standard Apache-2.0, BSD and MIT texts are added where a package carries none, instead of depending on ONNX Runtime's notices happening to contain them. The `SemanticRouter.AspNetCore` package's licence is now `MIT AND OFL-1.1`, with the font licences in the package. [docs/releases.md](docs/releases.md#the-embedding-models) gives the licence and source of each downloadable ONNX model. (#PR)
- The desktop app's `THIRD-PARTY-NOTICES.txt` lists the Rust crates statically linked into Velopack's updater, setup and stub (434 for Velopack 1.2.161, each listed for the platforms whose binaries link it) and Rust's standard library, with each crate's licence and its standard text. Velopack publishes no such list: [`deploy/third-party/velopack-crates.py`](deploy/third-party/velopack-crates.py) derives it from Velopack's `Cargo.lock` at the release tag, and CI fails when the workflows' `vpk`, the Velopack package and that list name different Velopack versions. (#222)
- Requests no longer wait for the SQLite state file. Usage, activity, feedback, warm caches, tool-call affinity and cooldowns are saved by one background writer, in batches; with SQLite state the gateway went from about 760 to 6,100 requests a second at 8 clients in the gateway benchmark, and p99 from 300 ms (busy-retry sleeps of 150 ms) to 6 ms. Stopping the router saves what is still waiting. A write that fails is counted (`semantic_router.state.dropped_writes`) and the dashboard's status says how many were lost. Activity is pruned every tenth of its cap instead of every 100 entries, and activity ids are reserved 1,024 at a time, ahead of need.
- The latency and prompt-cache figures of the latency-aware strategies are recomputed in the background. A request used to read a day of activity from the state file every 10 seconds while every other request waited for it.
- The in-memory warm prompt cache store is bounded (32,768 conversations) and no longer walks every entry on every write once it holds a few thousand.
- Identical prompts from unrelated requests no longer count as retries, so a monitor, a script or two sessions answering "continue" cannot get a healthy model left out of a route for a day. A retry is now the same prompt in the same conversation, before the conversation moved on; only the first repeat of a prompt gives feedback, and a short follow-up said again is not a retry.
- A backend that stops sending partway through a reply no longer holds the request open forever. The new connector setting `StallTimeout` (default: the connector's `Timeout`) is the time allowed between two pieces of a reply, for HTTP and CLI connectors. Before anything reached the client the next model answers; after, the client gets an error event in its protocol (a reply that is not streamed is broken off) and the model cools down.
- Requests that end early are recorded. A client that goes away mid-reply leaves an activity entry marked **cancelled** and a usage row (what the backend reported so far, or the estimated input), without holding it against the model. A backend that drops the connection mid-reply is recorded as failed and cooled down, and the client gets an error event instead of a truncated reply; the router no longer logs it as an unhandled exception.
- Traffic of many unrelated requests (scripts, evaluations, a shared gateway) no longer slows the router down over its first half hour: the conversation and retry trackers walked every entry on every request once they held a few thousand. They now prune at most every 15 seconds and keep at most 32,768 conversations and 16,384 answers, the least recently used going first.
- Where ONNX Runtime cannot run (Intel Macs, which it has no build for, and macOS before 14), `init` no longer sets up the in-process (`Onnx`) embeddings: it keeps `Hashing` and says to run an embedding model in LM Studio or Ollama. The dashboard's Embeddings page and `doctor` say why `Onnx` is not available there, and an `Onnx` choice that cannot load is reported as an embedding problem with that reason instead of a stack trace on every request. The release checks that each desktop build ships the native libraries it needs. (#238)
- `doctor` and [Network traffic](docs/network.md) name every host the downloads reach: Hugging Face's CDN (`*.hf.co`), which serves the ONNX model file through a redirect, and `release-assets.githubusercontent.com`, where desktop updates are now downloaded from. A failed model download names both Hugging Face hosts. (#241)
- **Delete all activity** says when another reader of the state file (a second router sharing it) kept a copy of the deleted rows in its write-ahead log past the busy timeout (`"complete": false` from `DELETE api/activity`), and that copy is removed after the router's next database operation instead of at the next prune. (#241)
- Desktop app: the dashboard's own links (its rail and tabs) opened in the web browser instead of the app window in some setups. A link the web view asks to open in a new window now stays in the window when it is the router's, and the router counts as itself under localhost, 127.0.0.1 or [::1]. Each link handed to the browser is noted in the app's log.
- Changes made on top of the running configuration (an utterance added from the dashboard, learned changes and undoing them) no longer undo a configuration applied a moment earlier: they are made again on top of it, up to three times. `POST api/config/save` saves exactly the version it read, or answers `409`.
- Adding an utterance from the dashboard, and applying or undoing a learned change, no longer saves configuration changes that were applied without saving: while the running configuration is unsaved they apply without saving too, and their answers say `"saved": false`.
- `doctor` labelled a CLI working directory it could not create as the CLI's `--version` failing; it now says what it is.
- The tool's prerequisite is the .NET 10 SDK (installing a .NET tool needs it), not "runtime or SDK".
- Dashboard: unapplied edits survive adding an utterance from Evaluate or Activity, a learned change, Save or Revert (moved onto the new configuration, or kept with a notice), and signing in again.
- Dashboard: text typed in the JSON editor or the evaluation set is kept across pages and renders, counts as unsaved when leaving, and is not replaced by **Show baseline** or **Load into editor** without asking.
- Dashboard: two model aliases or rate limits with the same name are flagged instead of one silently disappearing; **Add Claude Code defaults** no longer overwrites targets you set.
- Dashboard: removing an item no longer opens the item that moves into its place.
- Dashboard: Usage and Trends that fail to load say why with **Retry**, instead of asking again on every render.
- Dashboard: an error page from a proxy shows what it said instead of only "HTTP 502".
- Dashboard: **Discover** on a model shows its result under the field.
- Dashboard: no page scrolls sideways on a phone (Usage, Profiles, Evaluate, Overview); stat tiles stay two abreast.
- Dashboard: chart axes count in whole numbers without repeated labels; the Evaluate sweep's "too high"/"too low" labels no longer overlap.
- Dashboard: Usage right-aligns its figures and folds an empty Feedback card to one line.
- Dashboard: a failed prompt-tester Send or a plan with no eligible model says why and where to fix it.
- Dashboard: Memory without sources no longer shows Fit, Rescan and Clear sharing, nor two sets of add buttons; Evaluate with an empty set says what to do on the page itself.
- Deleting activity (`DELETE api/activity`, **Delete all activity**) could leave the deleted prompt previews in `state.db-wal` when another connection was reading the database at that moment (the dashboard, a second router on the same file). It now waits up to the busy timeout for the reader to finish before emptying the log, and logs a warning when it cannot.
- Dashboard accessibility (WCAG 2.2 AA, now checked with axe-core on every page, theme and width in CI): tables and the Live feed that scroll can be reached and scrolled from the keyboard; a model's **enabled** box is no longer inside its header's button and is big enough to hit; table columns without a visible heading have one for screen readers; the Feedback page's headings are in order; the charts are named with their figures; the Trends and Usage segmented buttons say which is pressed.
- Desktop app accessibility: the About, welcome and new Settings windows have headings, links that read as links, a logo hidden as decoration, and explanations read with their checkboxes; the update status and the router's problems are announced when they change; the focus moves to **Restart to update** after **Check now** finds one; the welcome window closes with Escape; the windows scroll instead of running off a short screen with large text; secondary text keeps full strength under high contrast; opening the dashboard window puts the focus in the page.
- Documentation site: the brand buttons' white text has at least 4.5:1 contrast in both themes, including on hover. The screenshots' alt text describes what they show (the memory map's colours included), the Mermaid diagrams have accessible titles and descriptions, links show page or section names instead of file names, and `semantic-router models` writes "why:" instead of an arrow glyph.
- Releases: a tag with a version suffix (`v1.0.0-rc.1`) is published as a GitHub prerelease with prerelease desktop update feeds, which installed desktop apps do not take, and its image is not tagged `:latest` ([#207](https://github.com/siebe41/SemanticRouter.NET/issues/207)).
- A state database that can't be used (corrupt, locked, or newer than the router) was reported only in the log. It is now one of the configuration warnings in `GET api/status` and on the dashboard, and `doctor` has a `state` line that fails on it ([#205](https://github.com/siebe41/SemanticRouter.NET/issues/205)).
- An install set up with 0.1.0–0.2.1 kept that release's routing defaults after every upgrade: Claude Code's default model name stayed an explicit Opus request (`"*opus*": "family:opus"`, fixed in 0.3.0 for new installs only), and the `quick-answers` route and later utterances never arrived. They now arrive on the first start of this release unless you changed those entries; if you did, set `*opus*` to `auto` yourself to have Claude Code's turns routed. `init` without `--force` also replaces an untouched template from any earlier release, as it says it will, instead of refusing ([#204](https://github.com/siebe41/SemanticRouter.NET/issues/204)).
- Desktop app: the Windows zip archives no longer carry 105 MB of native debug symbols, import libraries, the IIS module and XML documentation the app never uses (277 MB unpacked before, 176 MB now) ([#217](https://github.com/siebe41/SemanticRouter.NET/issues/217)).
- Desktop app: an update no longer turns a background service installed with `semantic-router service install` into one that runs the app, and uninstalling the app on Windows no longer removes it. The app reads which program the service runs, and its **Keep the router running in the background** setting names that program when it is not the app ([#214](https://github.com/siebe41/SemanticRouter.NET/issues/214)).
- Windows: the dashboard's setup left out, without a word, a CLI installed only as an npm script wrapper (`codex.cmd`), which the router does not start. It now lists it as found but not usable as installed, with where to get the `.exe`; `init`, `doctor` and the connector's error name that place too, and [CLIs on Windows](docs/providers.md#clis-on-windows) gives a Windows install for Claude Code, Codex and Copilot ([#211](https://github.com/siebe41/SemanticRouter.NET/issues/211)).
- Desktop app on macOS: macOS's web view carries out ⌘C, ⌘V, ⌘X, ⌘A and ⌘Z through the Edit menu, which the menu-bar app does not have, so pasting a key into the dashboard window could fail. On macOS it is a template image that follows the menu bar's light, dark and highlighted look; on Windows an icon with every size the notification area uses ([#215](https://github.com/siebe41/SemanticRouter.NET/issues/215)).

Routers sharing a state file count each other's usage within 2 seconds. The state file's usage table is rebuilt once, on the first start after the update. (#238)
- Activity entries were lost: concurrent requests could get the same id (the same `X-Prompt-Route-Id`), and two routers sharing a state file handed out the same ids, each replacing the other's entries without a word (about half the log). Every request now gets its own id, routers sharing a file take ids from a counter in it, and an id that is already stored is refused and logged instead of overwritten. Feedback ids too. Ids skip ahead after a restart. (#238)

### Security

- The release builds, scans and pushes the container image in separate jobs. Trivy and Syft, which download their binaries and vulnerability database at run time, now run in a job without permissions or caches instead of next to a token that can push to the registry, and the push checks that both the image it loads and the image the registry then holds are the one the build made. (#223)
- CLI connectors leave the router's own settings and keys out of the child's environment: `SemanticRouter__…` and `ROUTER_…` variables, the provider keys the setup reads (`OPENAI_API_KEY` and others), and any variable holding a secret the router resolved. `RemoveEnvironmentVariables` and `PromptInput` count as what a CLI runs, so the admin API changes them only with `AllowProcessSettings`. (#238)
- Gateway keys must have at least 16 characters (a shorter key in the configuration is refused, one from a reference is a warning), and an address that sends 20 wrong keys within 15 minutes gets `429` with `Retry-After` until the oldest is 15 minutes old. (#238)
- A repeated `TrustedGroupsHeader` is refused with `403`, as a repeated user header already was, so a client's own copy of the groups header cannot raise its role behind a proxy that appends to it. (#238)
- **Delete all activity** (`DELETE api/activity`) also deletes the feedback about the deleted entries (the judge's reason can quote the prompt and the answer), the prompt previews learned changes quote as evidence and the latest connector failure messages (a failed CLI run's output). A request still running, or waiting for the judge, when its activity is deleted is no longer stored again, and the judge drops it. (#241)
- The dashboard's API answers, the activity export and the live event stream are sent with `Cache-Control: no-store`, so a browser or the desktop app's web view no longer keeps prompt previews, the configuration or learned examples in its disk cache, where deleting activity could not reach them. The desktop app empties its web view's HTTP cache when its window first opens. (#241)
- Retention (`State:Retention`, capped by the machine policy's `MaxRetentionDays`) is enforced at start-up, every hour and when it changes, not only on every 100th write, and the write-ahead log is truncated after a prune. The activity export, the feedback summary and tuning leave out rows past retention even before they are pruned. (#241)
- An unreachable HTTP connector's log line no longer includes credentials written into its `BaseAddress` (`https://user:key@host`), and such credentials, and key-like query values, are redacted wherever the router redacts keys. (#241)
- Another account on the same machine is no longer trusted as "this machine": the router asks the operating system who opened each loopback connection (Linux, macOS, Windows), and another user is a remote client that needs a dashboard token or a gateway key and is not served by subscription CLI connectors. Root and LocalSystem still count as the router's own account. `SemanticRouter:Network:TrustOtherLocalAccounts` restores the old behaviour for a router that serves everyone who signs in to the machine. (#235)
- Over the admin API, every value the router resolves is held to the secret-reference rules, not only header names that look secret, and an `${env:…}` reference a setting did not have before is accepted only from this machine or as a provider preset's key for that provider's address. (#235)
- `GET api/routes/health`, which embeds every utterance, is refused from other sites and to the read-only role, and is recorded in the audit log, like the other endpoints that spend embedding calls. (#235)
- The judge does not send a remote client's request and answer to a subscription CLI or Copilot connector that does not allow remote clients. (#235)
- Desktop app: the app window hands only `https` and `http` links to your browser. A link or navigation to any other scheme (`file:`, a network share, `ms-msdt:`, `search-ms:`, `javascript:`, `data:` or another program's protocol) is dropped and noted in the app's log instead of being passed to the operating system, and the app acts on a message from the page only while the window shows the router. (#238)
- Desktop app: a release build ignores `SEMANTICROUTER_UPDATE_SOURCE` unless the machine policy sets the new `Updates:AllowCustomFeed`, and an update feed (from the policy or the variable) must be HTTPS or a folder; plain HTTP is accepted only to this machine, and other schemes are refused. (#238)
- Desktop app: with `Updates:Publisher` set on Windows, an update is also refused when its `*.runtimeconfig.json` or `*.deps.json` would make the .NET host load code from outside the package (`additionalProbingPaths`, `STARTUP_HOOKS` and the host's other properties, paths that leave the app's folder) or it has a `*.runtimeconfig.dev.json`. (#238)
- On Windows, a `SEMANTIC_ROUTER_HOME` or `SEMANTIC_ROUTER_KEYS_DIR` folder the router creates outside your profile is readable only by your account, SYSTEM and Administrators, instead of inheriting permissions that usually let every user read it; `doctor` warns when an existing configuration or key ring folder can be read by `Users`, `Everyone` or `Authenticated Users`. (#238)
- The in-process (`Onnx`) embeddings no longer send usage data to Microsoft or write a device id to `~/.cache/Microsoft/DeveloperTools/.onnxruntime` on Linux and macOS, offline mode included: the router sets `ORT_DISABLE_TELEMETRY=1` in its own environment before ONNX Runtime loads (a value you set is kept), and the container image and the services `service install` writes set it too. `doctor` says whether ONNX Runtime's telemetry is off. (#238)

## [0.3.0] - 2026-10-16

### Security

- Machine-wide policy that the user's configuration cannot override, read from `HKLM\Software\Policies\SemanticRouter`, macOS managed preferences or `/etc/semantic-router/policy.json`: turn off connector types and CLI presets, limit endpoints and the hosts that count as local, require local-only, cap prompt storage and retention, make the dashboard read-only or turn it off, control desktop updates and turn features off. A policy that cannot be read stops the router. See [docs/enterprise.md](docs/enterprise.md). (#142)
- `init` does not add, or ask about, CLIs that the machine policy turns off. (#146)
- Offline mode (`Network:Offline` with `Network:AllowedHosts`, or `Offline` in the machine policy): connectors, embeddings and webhooks reach only this machine and the allowed hosts, CLI and Copilot connectors are off, and the ONNX model is never downloaded. (#147)
- Remote gateway clients need a key: with no `Middleware:GatewayKeys` they get 401 (`AllowUnauthenticatedRemoteClients` restores the old behaviour), and a key reference that does not resolve no longer opens the gateway. The container image reads `ROUTER_GATEWAY_KEY`. (#129)
- Default limits for remote clients (`Middleware:RemoteRequestsPerMinute`, 120) and CLI queues (`MaxQueue`, 16), and `ForwardedHeaders:KnownProxies`/`KnownNetworks` to trust `X-Forwarded-For` only from named proxies. (#129)
- Web pages cannot use the gateway through DNS rebinding or a foreign `Origin`; `/v1/models`, `count_tokens` and `/semantic-router/classify` follow the same gateway-key rule as the chat endpoints. (#114)
- Dashboard responses forbid framing (`frame-ancestors 'none'`, `X-Frame-Options: DENY`) and send `nosniff` and `no-referrer`; the dashboard bundles its fonts and sends a strict Content-Security-Policy. (#114, #129)
- The admin API cannot change what a CLI runs (program, arguments, environment, home directory) or which paths memory sources read, unless `Dashboard:AllowProcessSettings` is on. (#114, #144)
- The read-only dashboard role can no longer trigger calls that cost money or scan the disk (evaluate, classify, embeddings test, discover, check, memory refresh); dashboard sessions expire after `Dashboard:SessionLifetime` (12 hours), and wrong tokens are throttled per address. (#144)
- Dashboard identity from an authenticating reverse proxy (`Dashboard:TrustedIdentityHeader`, believed only from `KnownProxies`), the real actor on every configuration change, and an append-only audit log (`GET /router/api/audit`, an Audit log page, `State:Retention:AuditDays`). (#150)
- A `Metrics` dashboard role (`Dashboard:MetricsToken`, or `Metrics` in `TrustedIdentityRoles`) that sees figures only, never prompt or reply text. Signing out ends the session on the server, and an admin can sign out every session (`POST /router/api/session/revoke-all`); sessions from before the upgrade sign in once more. (#161)
- With `State:StorePrompts: Off`, a failed CLI run's output and the judge's reason for a grade are not stored or logged either; `Redacted` masks credentials in them. (#162)
- Local-only routing holds in more cases: a failed classification stays local while any route is local-only, a conversation kept local stays local (including named cloud models), local-only prompts stay off remote embedding endpoints (`Embeddings:IsLocal`), and the judge respects routing profiles. (#114)
- Secrets: CLI environment variables and more header names (auth, cookie, password, credential, session, signature) are masked; masked or stored keys are never sent to a connector that now points somewhere else; the configuration history keeps no secrets; keyed requests do not follow redirects; webhook URLs are not logged. (#114, #116)
- Keys written into addresses (`user:key@`, key-named query values) are masked in the admin API, the configuration history and every address the dashboard and `doctor` show. (#117, #129)
- CLIs run in a working directory only the user can write to and start by full path; a Custom CLI's `{prompt}` cannot become an option; the router's files are readable by their owner only. (#114)
- The data-protection key ring is encrypted at rest: to a certificate (`DataProtection:Certificate`) on any OS, with DPAPI for `SEMANTIC_ROUTER_KEYS_DIR` on Windows; otherwise owner-only permissions and a start-up warning. `doctor` says how the keys are protected. (#149)
- Stored prompts: `State:StorePrompts` (`Redacted` by default, masking credentials in previews; `On`; `Off`), `State:Retention`, and a purge (`DELETE /router/api/activity`, "Delete all activity") that leaves nothing readable in the database files. (#129)
- Webhooks carry no prompt or reply text unless `Notifications:IncludeDetails` is on, and the stored project label is a hash of the client's `user_id`, never the id. (#144)
- Prompted tool calls are harder to forge: a random fence label per run that never reaches the client, defused tool results, `PromptedToolParsing: Strict` (opt-in), calls copied from a tool result kept as text in both modes, and a prompted-call count in the activity log. (#129, #152)
- No outbound traffic you did not configure: no web fonts from other hosts, Claude Code started without its auto-updater and non-essential traffic, Codex with update checks and analytics off. `doctor` lists every host the router will contact. (#129, #143)
- Desktop updates: `Updates:Publisher` requires an update to be code-signed by a given publisher before it is applied, and the updater refuses feeds over plain HTTP other than loopback. (#142, #151)
- Verifiable releases: build provenance attestations for every asset, `SHA256SUMS`, CycloneDX SBOMs, a keyless cosign signature and attestations on the container image, and `THIRD-PARTY-NOTICES.txt`. See [docs/releases.md](docs/releases.md). (#145)
- Release pipeline: a tag must be on `main`, tests pass before anything publishes, the desktop app is built in jobs without secrets, and the image is built and scanned (Trivy) before the registry login. CodeQL and OpenSSF Scorecard run on the repository. (#129)
- The container runs on a chiseled ASP.NET Core image with no shell, with both base images pinned by digest. (#129)
- NuGet restores are locked to committed `packages.lock.json` files in CI, the release and the container build. (#148)
